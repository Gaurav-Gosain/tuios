tuios 0.13.3 is a security and fix release. It closes four issues that @cr2007 reported privately, and I recommend it to everyone. It also fixes a regression from v0.13.2 in the focus keys, and a few bugs you reported.

Upgrading from v0.13.1 or later is live on macOS and Linux: install, then run `tuios daemon upgrade`, and every program in your panes keeps running.

```bash
brew install tuios                     # Homebrew (macOS, Linux)
yay -S tuios-bin                       # AUR (tuios-web-bin for the web server)
nix run github:Gaurav-Gosain/tuios     # Nix
curl -fsSL https://raw.githubusercontent.com/Gaurav-Gosain/tuios/main/install.sh | bash
go install github.com/Gaurav-Gosain/tuios/cmd/tuios@v0.13.3
docker run -it --rm ghcr.io/gaurav-gosain/tuios:v0.13.3
```

A binary installed by the script or from an archive updates with `tuios update`.

## Security

Thanks to @cr2007 for four careful reports, each with the lines and a way to reproduce it.

- **A removed paired device loses its access.** `tuios hosts remove DEVICE` now removes the key that `tuios pair` added to `~/.ssh/authorized_keys`, not only the `[hosts.DEVICE]` table. Before, the phone could still log in, and after a restart it got the default rights. The file is now written in one step, so a failed write cannot cut your own keys. A key pinned to a name with no table can do nothing, also on a link that is already open. If you removed a paired device before this release, run `tuios hosts remove DEVICE` again to remove its key. [GHSA-4j54-9xgf-cq7g](https://github.com/Gaurav-Gosain/tuios/security/advisories/GHSA-4j54-9xgf-cq7g) ([#2162](https://github.com/Gaurav-Gosain/tuios/pull/2162))
- **Shell markers cannot fill the daemon's memory.** A program could print one OSC 133 prompt mark and many command marks, and each one read every line back to the prompt. The capture now stops at 64 lines and 16 KiB, and a repeated mark reuses the text it has. This is in `tuios.dev/vt` v0.3.3. [GHSA-w23r-7frv-qfhg](https://github.com/Gaurav-Gosain/tuios/security/advisories/GHSA-w23r-7frv-qfhg) ([#2163](https://github.com/Gaurav-Gosain/tuios/pull/2163))
- **Programs in panes cannot take every daemon connection.** Panes, hooks and plugins together hold at most 896 of the 1024 connections, so 128 stay for your own client and `tuios` commands. One pane holds at most 64. A program in a pane also no longer draws on your own read budget. [GHSA-jv4p-w86m-gr3h](https://github.com/Gaurav-Gosain/tuios/security/advisories/GHSA-jv4p-w86m-gr3h) ([#2170](https://github.com/Gaurav-Gosain/tuios/pull/2170))
- **Hooks and `exec` lines get a clean environment.** Daemon hooks, plugin commands, `exec` lines and task verify commands now start from the environment a pane gets. Before, a daemon started by `tuios restart-server` in a pane placed them in that pane, and they could act as it. [GHSA-v98m-7pr7-xv88](https://github.com/Gaurav-Gosain/tuios/security/advisories/GHSA-v98m-7pr7-xv88) ([#2171](https://github.com/Gaurav-Gosain/tuios/pull/2171))
- The daemon decides whether a caller runs in one of its panes by the processes it started. Before, a pane program could pass as you after the daemon took over panes it did not start. ([#2142](https://github.com/Gaurav-Gosain/tuios/pull/2142))

## Fixes

- Keys bound to `terminal_focus_up` and `terminal_focus_down` work again with the Neovim navigator. This broke in v0.13.2. Thanks to @5c077m4n for the report. ([#2161](https://github.com/Gaurav-Gosain/tuios/pull/2161))
- `tuios cp -m` no longer deletes the only copy when the source and the target are one file, through a link or on a disk that ignores case. Thanks to @cr2007. ([#2166](https://github.com/Gaurav-Gosain/tuios/pull/2166))
- A pane that runs an agent from a versioned interpreter, such as Hermes on `python3.14`, is detected again. Thanks to @sebapawlak. ([#2168](https://github.com/Gaurav-Gosain/tuios/pull/2168))
- With the omp v2 extension, the pane follows omp itself, so the agent state and a claimed task card stay right through a turn. Thanks to @sebapawlak. ([#2169](https://github.com/Gaurav-Gosain/tuios/pull/2169))
- The dock stops offering an undo when the undo window ends, and `u` names the window you set. Thanks to @Gsirawan. ([#2159](https://github.com/Gaurav-Gosain/tuios/pull/2159))
- `tuios run` waits for the first prompt in a fresh pane, and one slow frame no longer cuts the next workspace slide. ([#2154](https://github.com/Gaurav-Gosain/tuios/pull/2154))
- A host link follows the person's input, not the frames a client sends on its own. ([#2156](https://github.com/Gaurav-Gosain/tuios/pull/2156))
- A folder report from a pane no longer undoes a window move. ([#2146](https://github.com/Gaurav-Gosain/tuios/pull/2146))
- A new workspace takes the tiling mode of the one it was opened from. ([#2144](https://github.com/Gaurav-Gosain/tuios/pull/2144))

## Compatibility

A v0.13.3 client and daemon work with v0.12 and v0.13 peers. Code paths for peers older than v0.12 are gone, so the binary is a little smaller. ([#2153](https://github.com/Gaurav-Gosain/tuios/pull/2153)) ([#2155](https://github.com/Gaurav-Gosain/tuios/pull/2155))
